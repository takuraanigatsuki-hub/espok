## 2. Ключевые компоненты

### 2.1. Case Management Service

**Назначение:** сквозная карточка расследования.

**Функции:**
- регистрация и ведение единого ID расследования (EPSOK-CASE-UUID);
- привязка поддел по ведомствам и регионам;
- хронология событий (timeline);
- управление составом рабочей группы;
- статусы: зарегистрировано → возбуждено → расследуется → приостановлено → передано / завершено.

**Хранение:** PostgreSQL (реляционная модель) + события в Kafka.

### 2.2. Link Intelligence Service

**Назначение:** построение и анализ графа связей.

**Типы узлов:**
- Person (физлицо)
- Organization (юрлицо)
- Phone, IMEI, IMSI
- Vehicle (ГРЗ)
- BankAccount, CryptoWallet
- Address, IPAddress
- EvidenceItem
- Case (дело)

**Типы рёбер:**
- `COMMUNICATED_WITH`, `CO_SUSPECT`, `OWNS`, `REGISTERED_AT`
- `TRANSACTION`, `EMPLOYED_BY`, `RELATED_CASE`
- `CUSTODY_TRANSFER`, `WITNESSED`

**Хранение:** Neo4j / JanusGraph. Доступ к узлу — только при наличии прав на связанное дело.

**Алгоритмы:**
- поиск кратчайших путей между узлами;
- выявление сообществ (community detection);
- сопоставление с известными MO-шаблонами.

### 2.3. Interagency Request Hub

**Назначение:** цифровой конвейер межведомственных запросов.

**Правовая привязка:** каждый тип запроса — к ФЗ/УПК ведомства-исполнителя (см. [agency-functions.md](technical/agency-functions.md), [agency-registry.yaml](../configs/agency-registry.yaml)).

**Жизненный цикл запроса:**
```
DRAFT → SUBMITTED → ACCEPTED → IN_PROGRESS → FULFILLED
                                              ↘ REJECTED (с мотивировкой)
                                              ↘ ESCALATED (просрочка SLA)
```

**SLA по типам (целевые):**
| Тип запроса | SLA |
|---|---|
| Проверка по базам МВД | 4 часа |
| Выписка ФНС | 1 раб. день |
| Запрос Росфинмониторинг | 1–3 раб. дня |
| Таможенные данные ФТС | 3 раб. дня |
| Судебное решение / санкция | по регламенту суда |

**Интеграция:** СМЭВ 3.x, REST-адаптеры для ведомств с прямым API.

### 2.4. Evidence Registry

**Назначение:** учёт вещественных и цифровых доказательств.

**Функции:**
- регистрация с вычислением SHA-256 / ГОСТ Р 34.11-2012;
- QR-код для физических объектов;
- журнал передачи (custody chain) — append-only;
- привязка к протоколам следственных действий;
- экспорт пакета для суда.

**Хранение:** метаданные — PostgreSQL; файлы — зашифрованное object storage (MinIO / Ceph).

### 2.5. Deadline Engine

**Назначение:** автоматический расчёт процессуальных сроков.

**Правила (примеры):**
- дознание: 2 месяца (ст. 223 УПК), продление до 6;
- следствие: 2 / 3 / 6 / 12 месяцев (ст. 162);
- содержание под стражей: контроль общих сроков;
- приостановление (ст. 208): пауза таймеров;
- экспертизы: отдельные таймеры.

**Календарь:** производственный календарь РФ, учёт переносов праздников.

### 2.6. Analytics & MO Engine

**Назначение:** федеральная аналитика без нарушения тайны следствия.

**Режимы:**
- **Оперативный:** по открытым делам пользователя (полные данные).
- **Аналитический:** обезличенные кластеры MO (без ФИО, с хешированными идентификаторами).
- **Стратегический:** агрегаты для руководства (регион, статья, динамика).

**ML-модели (on-premise):**
- кластеризация MO;
- anomaly detection по потокам СОДЧ;
- NLP для извлечения сущностей из протоколов (опционально, фаза 3).

### 2.7. Audit Log (WORM)

**Назначение:** неизменяемый журнал всех действий.

**Фиксируется:**
- кто, когда, с какого АРМ;
- какое действие (просмотр, экспорт, запрос, изменение);
- объект (ID дела, узел графа, доказательство);
- результат (успех / отказ / основание отказа).

**Технология:** append-only storage, криптографическая цепочка блоков (blockchain-подобная, без публичного блокчейна).

### 2.8. OSINT Intelligence Service

**Назначение:** контролируемый сбор данных из открытых источников в рамках дела — замена неформальных «ботов пробива» для легального OSINT-слоя.

**Компоненты:**
- **Orchestrator** — очередь задач, RBAC (POL-006), маппинг в граф, шифрование ПДн, интеграция с Evidence Registry;
- **Worker Pool** — изолированные экземпляры SpiderFoot (Python), whitelist модулей, ephemeral storage;
- **Proxy/WAF** — исходящий интернет только для Worker, с журналированием URL.

**Не заменяет:** межведомственные запросы (ГИАЦ, ИБД, ФНС, РФМ) — см. Interagency Request Hub.

**Хранение:** PostgreSQL (`osint_scans`, `osint_findings` с TTL); сырой SQLite SpiderFoot не персистится.

**Фаза внедрения:** 2 (2029–2030).

*Подробнее: [technical/osint-service.md](technical/osint-service.md)*

### 2.9. Horizon Intelligence Layer

**Назначение:** федеральный когнитивный слой — ускорение поиска подозреваемых и скрытых связей **без** базы всех граждан.

**Компоненты:**
- **Serendipity Engine** — автопересечение hash между активными делами регионов;
- **Ghost Link Detector** — скрытые пути через номиналов и посредников;
- **Temporal Co-occurrence Reconstructor** — хронология на данных межвед запросов;
- **MO Resonance Matcher** — сопоставление с федеральными MO-шаблонами;
- **Investigation Digital Twin + PRO** — симуляция и рекомендация следующего легального запроса;
- **Federated Identity Resolution** — гипотеза «тот же человек» через hash + ГИАЦ.

**Принцип:** Zero Citizen Database — только хеши в федеральном индексе, ПДn по СМЭV.

**Фаза:** 3 (2031–2032). *См. [technical/horizon-intelligence.md](technical/horizon-intelligence.md)*

### 2.10. Tech Admin Console

**Назначение:** изолированный контур технического администрирования для операторов ЦОД — без доступа к содержимому дел.

**Возможности (7):**
- **SVC** — мониторинг микросервисов и SLA;
- **USR** — provisioning учётных записей (с согласованием ADMIN);
- **INT** — адаптеры СМЭВ и ведомств, ротация сертификатов;
- **CFG** — feature flags и региональная конфигурация;
- **OSW** — OSINT Worker Pool и whitelist модулей;
- **HZM** — модули Horizon и Bloom-индекс;
- **OPS** — retention purge, ротация ключей, окна обслуживания.

**Размещение:** отдельный host `admin.epsok.gov.ru`, namespace `epsok-admin`, POL-008.

**Фаза:** 1 (базовый SVC, USR, INT) → 2 (OSW, HZM, OPS).

*Подробнее: [technical/tech-admin-console.md](technical/tech-admin-console.md)*

## 3. Сегментация инфраструктуры

```
┌─────────────────────────────────────────────────────────┐
│  КОНТУР А (открытый)     │  Справочники, SLA, публичные │
│                          │  регламенты, ЕСИА             │
├──────────────────────────┼───────────────────────────────┤
│  КОНТУР Б (служебный)    │  Карточки дел, запросы,       │
│                          │  граф (без грифа)             │
├──────────────────────────┼───────────────────────────────┤
│  КОНТУР В (грифованный)  │  ОРД, особо важные дела,      │
│                          │  данные ФСБ                   │
└──────────────────────────┴───────────────────────────────┘
         ▲                           ▲
         │         air gap /         │
         └───── API с mTLS ──────────┘
```

**Размещение:**
- ЦОД уровня ГосСОПКА (основной);
- региональные узлы (8–10 федеральных округов) для снижения latency;
- резервный ЦОД (DR).

## 4. Технологический стек (рекомендуемый)

| Слой | Технология | Обоснование |
|---|---|---|
| Backend | Java 21 / Spring Boot или C# / .NET 8 | Принят в госсекторе, сертифицируемые сборки |
| Frontend | React + TypeScript | Единый UI-kit (Госуслуги / Atlas) |
| API | REST + OpenAPI 3; СМЭВ XML | Совместимость |
| БД транзакций | PostgreSQL 16 | Надёжность, JSONB |
| Граф | Neo4j Enterprise / JanusGraph | Link analysis |
| Поиск | OpenSearch | Полнотекст, логи |
| Очереди | Apache Kafka | Событийная архитектура |
| Кэш | Redis Cluster | Сессии, справочники |
| Файлы | MinIO (S3-compatible) | On-prem object storage |
| Контейнеры | Kubernetes (ROS / Baikal) | Оркестрация |
| Мониторинг | Prometheus + Grafana | SLA, алерты |
| SIEM | Kaspersky NG / RuSIEM | ГосСОПКА |

**СКЗИ:** по решению ФСБ — ViPNet, Континент, другие сертифицированные средства.

## 6. Отказоустойчивость

- RTO: 4 часа (критичные сервисы)
- RPO: 15 минут (реplication PostgreSQL)
- Георезервирование: актив-passive между ЦОД
- Circuit breaker для адаптеров ведомств
