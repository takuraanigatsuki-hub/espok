# Модель информационной безопасности ЕПСОК

## 1. Классификация системы

| Параметр | Значение |
|---|---|
| Тип | Государственная информационная система (ГИС) |
| Объект КИИ | Да (187-ФЗ), категорирование — значимый / высокозначимый |
| ИСПДн | Да, уровень защищённости **УЗ-1** (или К1 по Приказу ФСТЭК № 21) |
| Грифованность | Сегменты с гостайной — отдельный контур |

---

## 2. Принципы безопасности

1. **Zero Trust** — не доверять по умолчанию, проверять каждый запрос.
2. **Least Privilege** — минимально необходимые права.
3. **Defense in Depth** — многоуровневая защита.
4. **Audit Everything** — полная трассируемость действий.
5. **Data Sovereignty** — данные не покидают контур РФ.

---

## 3. Аутентификация и управление доступом

### 3.1. Аутентификация

- **ЕСИА** — первичная идентификация госслужащего.
- **Ведомственная 2FA** — аппаратные токены (Рutoken, JaCarta) или мобильное приложение с ГОСТ-криптографией.
- **mTLS** — между микросервисами и адаптерами.
- **Сессии** — timeout 15 мин неактивности, повторная аутентификация для экспорта.

### 3.2. Модель ABAC

```
ДОСТУП = f(роль, ведомство, регион, номер_дела, стадия, контур, гриф)
```

Пример политики:
```
Следователь МВД может READ узел Person в графе
  IF узел связан с делом, где пользователь — ответственный
  AND стадия_дела IN (расследуется, возбуждено)
  AND контур = следственный
```

См. [technical/rbac-matrix.md](technical/rbac-matrix.md).

## 4. Защита данных

### 4.1. Шифрование

| Объект | В покое | В передаче |
|---|---|---|
| БД PostgreSQL | TDE / pgcrypto (ГОСТ) | — |
| Граф Neo4j | Шифрование дисков | TLS 1.3 + ГОСТ |
| Object Storage | AES-256 / GOST | mTLS |
| Резервные копии | Шифрование, отдельные ключи | Защищённый канал |
| Журнал аудита | WORM + подпись | Append-only API |

### 4.2. Ключевая инфраструктура

- **HSM** — хранение ключей шифрования.
- **Разделение обязанностей** — администратор платформы не имеет доступа к содержимому дел.
- **Ротация ключей** — по регламенту ФСБ.

### 4.3. Обезличивание (аналитический контур)

- Необратимое хеширование идентификаторов (salt per-tenant).
- k-anonymity для агрегатов (минимум k=5 записей в ячейке).
- Запрет re-identification в политиках.

## 5. Сетевая безопасность

```
Internet ──X── (нет прямого доступа)

Ведомственные сети ── VPN / MPLS ── DMZ ── API Gateway ── App Tier ── Data Tier
                                      │
                                   WAF, IDS/IPS
                                      │
                              ГосСОПКА (SOC)
```

- Сегментация VLAN / micro-segmentation (Kubernetes Network Policies).
- Air gap между грифованным и негрифованным контурами — API-only bridge с DLP.

## 6. Мониторинг и реагирование

| Компонент | Назначение |
|---|---|
| SIEM (RuSIEM / Kaspersky NG) | Корреляция событий, алерты |
| DLP | Предотвращение утечек при экспорте |
| UEBA | Аномалии поведения пользователей |
| ГосСОПКА | Федеральный мониторинг КИИ |
| Red Team / Pentest | Ежегодно, по согласованию с ФСТЭК |

**Триггеры эскалации:**
- >100 записей экспортировано за сессию
- Доступ к делу вне региона пользователя без основания
- Массовый просмотр ПДн (>50 карточек/час)
- Неудачные попытки аутентификации (>5)

## 7. Сертификация и аттестация

| Этап | Орган | Результат |
|---|---|---|
| Предварительная классификация | ФСТЭК | Класс ИС, меры защиты |
| Аттестация ИС | ФСТЭК / лицензиат | Аттестат соответствия |
| СКЗИ | ФСБ | Разрешение на применение |
| Категорирование КИИ | Минцифры / НКЦКИ | Категория значимости |
| Пентест | Аккредитованная лаборатория | Отчёт, устранение |

---

## 8. Резервное копирование и восстановление

- RPO: 15 мин (синхронная реплика PostgreSQL).
- RTO: 4 ч (failover на резервный ЦОД).
- Резервные копии — в geographically separate ЦОД, зашифрованы.
- Тестирование восстановления — ежеквартально.

---

## 9. Безопасность разработки (DevSecOps)

- Статический анализ (SAST) — в CI/CD.
- Сканирование зависимостей (SCA).
- Code review — обязателен для модулей доступа и аудита.
- Сборки — только из сертифицированных репозиториев (внутренний Nexus).
- Secrets — Vault, не в коде.

---

## 10. Инциденты

1. Обнаружение → SOC (15 мин).
2. Локализация → изоляция сегмента (1 ч).
3. Уведомление НКЦКИ / ГосСОПКА (по 187-ФЗ).
4. Расследование → WORM-журнал + форензика.
5. Отчёт руководству и прокуратуре (при утечке ПДн).
