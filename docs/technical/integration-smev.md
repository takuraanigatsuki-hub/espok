# Интеграция с СМЭВ и ведомственными ИС

## 1. Принцип интеграции

ЕПСОК выступает **потребителем и поставщиком** видов сведений в СМЭВ 3.x:

- **Исходящие запросы** — от следователя через Interagency Request Hub → адаптер → СМЭВ → ведомство.
- **Входящие ответы** — асинхронно через очередь, привязка к caseId и requestId.
- **Push-уведомления** — подписка на события (новое дело в регионе, SLA breach).

**ЕПСОК не заменяет СМЭВ** — использует его как транспорт там, где нет прямого API.

## 3. Архитектура адаптера

```
Interagency Request Hub
        │
        ▼
┌───────────────────┐
│ Adapter Registry  │  ← конфиг типов запросов, SLA, XSD
└─────────┬─────────┘
          │
    ┌─────┴─────┬─────────────┐
    ▼           ▼             ▼
 SMEVAdapter  DirectAPI    BatchAdapter
    │           │             │
    ▼           ▼             ▼
  СМЭВ       REST/gRPC      SFTP (legacy)
```

### 3.1. SMEVAdapter

- Формирование XML по XSD вида сведений
- Подпись ЭЦП (КЭП ведомства)
- Отправка через СМЭВ 3.x
- Polling / callback на ответ
- Retry с exponential backoff

### 3.2. DirectAPI

- Для ведомств с выделенным защищённым API (СК, часть МВД)
- mTLS, JWT от ЕСИА + scope delo:{caseId}

### 3.3. BatchAdapter

- Для legacy (SFTP выгрузки) — временная мера на Фазе 1

## 5. Обработка ответов

```json
{
  "requestId": "uuid",
  "caseId": "uuid",
  "status": "fulfilled",
  "receivedAt": "2028-03-15T14:30:00+03:00",
  "payload": { "...": "структура по типу" },
  "signatureVerified": true,
  "linkedGraphNodes": ["person-uuid", "org-uuid"]
}
```

Автоматическое создание узлов в графе — по конфигурации типа запроса (с согласия следователя).

## 6. Ошибки и эскалация

| Код | Действие |
|---|---|
| TIMEOUT (> SLA) | status=escalated, уведомление руководителю и ведомству |
| REJECTED | rejectionReason обязателен, уведомление следователю |
| SMEV_FAULT | Retry 3x, затем ticket в поддержку |
| SIGNATURE_INVALID | Отклонить ответ, инцидент безопасности |

---

## 7. Требования к ведомствам (для соглашений)

1. Назначить ответственного за интеграцию с ЕПСОК.
2. Обеспечить SLA по типам запросов (таблица выше).
3. Предоставить тестовый контур для пилота.
4. Участвовать в приёмочных испытаниях адаптера.
5. Не взимать плату за запросы в рамках расследования (внутригос.).
